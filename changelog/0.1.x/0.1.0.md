# 0.1.0 — 2026-11-02

## Added

- **`handover scan`**: rollouts of base Qwen3.5 with upstream's `BridgeHost` (the calc firmware on the reference RV32 machine) forcing each tool response, decoded on upstream's `BatchDecoder` (continuous batching, CUDA-graph steps) with in-graph temperature / top-k / top-p sampling; greedy or sampled, `nudge` / `bare` prompt variants, each rollout appended to resumable JSONL as it finishes.
- **`handover metrics`**: per (set, variant) exactness, hand-over, answers taken from the machine, budget hits, error and repeated calls, Qwen tokens, solved problems.
- **`handover select`**: rejection sampling to exact, machine-answered, finished, non-repeating rollouts; refuses eval-split problems.
- **`handover train`**: LoRA SFT on the language model's projections, loss on Qwen-written tokens only, trained under the `bare` prompt by default.
- **`handover export`**: folds an adapter into a copy of the base checkpoint with the base's keys, shards and index, ready for `python -m chipformer.rv.merge`.
- **`synth` training set**: seeded multiplications, exact divisions, multi-term expressions and large-number word problems.
- **Makefile recipes** for upstream's merge, `textcheck`, rv1 / pytool evals and IR replay.
- **`firmware/calc-bridge.elf`**: upstream's calc firmware at `bec1a0c`, MIT.
